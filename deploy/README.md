# MikroLink روی MikroTik

این مسیر نمونه برای **RouterOS 7.24.6 CHR روی EC2** با دامنهٔ بی‌طرف `vpn.example.com` آماده شده است. دامنهٔ واقعی باید فقط هنگام استقرار و خارج از مخزن وارد شود. packageهای `container` و `user-manager`، یک volume پایدار و دامنه عمومی لازم‌اند. رکورد A دامنه باید به روتر اشاره کند و TCP/80 برای صدور گواهی ACME در دسترس باشد؛ رکورد AAAA را فقط در صورت پیکربندی کامل IPv6 قرار دهید. در AWS، Security Group باید TCP/80، TCP/443، پورت OpenVPN و UDP/51820 و UDP/500,4500 را مجاز کند؛ REST روی 8443 نباید عمومی شود. برای فعال کردن Container در CHR، بعد از `/system/device-mode/update container=yes` باید VM را در EC2 **Stop و Start** کنید؛ reboot معمولی تأیید را انجام نمی‌دهد. اگر از IP عمومی ثابت استفاده نمی‌کنید، پس از Start دوباره رکورد DNS را بررسی کنید. [Container](https://manual.mikrotik.com/docs/containers/) · [ACME](https://manual.mikrotik.com/docs/authentication-authorization-accounting/certificates/) · [Reverse Proxy](https://manual.mikrotik.com/docs/network-management/proxy/reverse-proxy/)

1. Image سرویس را از `server/Dockerfile` برای معماری روتر بسازید و در registry منتشر کنید. مقدار `containerImage` باید همان image منتشرشده باشد. RouterOS Docker Engine اجرا نمی‌کند؛ image سازگار با OCI را دریافت می‌کند.
2. packageهای `container` و `user-manager` را نصب کنید. روی روتر دستور `/system/device-mode/update container=yes` را اجرا و با دکمه یا خاموش/روشن کردن دستگاه تأیید کنید. دیسک خارجی را به روتر وصل کنید و نام آن را در `disk` بگذارید.
3. برای ساخت خودکار فایل محلی با چهار رمز متفاوت و تصادفی اجرا کنید: `node deploy/create-site.mjs vpn.example.com <registry-image> disk1 deploy/site.json`. این فایل را منتشر نکنید. اگر از نمونه استفاده می‌کنید، `site.example.json` را کپی کرده و چهار رمز واقعی متفاوت جایگزین کنید.
4. `node deploy/generate-routeros.mjs deploy/site.json deploy/mikrolink-install.rsc` را اجرا کنید. فایل خروجی شامل رمزهاست. آن را به روتر منتقل کنید و فقط یک بار با `/import file-name=mikrolink-install.rsc` اجرا کنید. اگر گواهی ACME هنوز آماده نبود، پس از بررسی DNS و TCP/80 اسکریپت را دوباره اجرا کنید.
5. پس از پایان استخراج image، `/container/start mikrolink-api` را اجرا کنید. سپس `https://<publicHost>/health` را بررسی کنید.
6. کاربران و پروفایل‌ها را با manifest و ابزار `server/src/admin-cli.js` ایجاد کنید. برای تغییرهای بعدی نیز همین ابزار را اجرا کنید؛ ورود دستی تک‌تک کاربران یا کانفیگ‌ها در RouterOS لازم نیست.

اسکریپت WireGuard، OpenVPN، IKEv2، RADIUS/User Manager، REST خصوصی، reverse proxy و قوانین شبکه را می‌سازد. REST روی پورت 8443 فقط از شبکه veth کانتینر پذیرفته می‌شود؛ API عمومی روی HTTPS/443 قرار می‌گیرد. نام اینترفیس WireGuard و زیرشبکه‌ها با تنظیمات `server` هماهنگ‌اند.

**پیش از استفاده واقعی:** خروجی اسکریپت و قوانین firewall را روی مدل و پیکربندی روتر خود بررسی کنید. تولید فایل در این پروژه آزموده شده، ولی اجرای RouterOS و اتصال VPN بدون روتر و دستگاه اندروید واقعی در این محیط آزمایش نشده است. فایل `site.json` و فایل `.rsc` را پس از نصب از رایانه مدیریتی حذف یا در محل امن نگه دارید.
